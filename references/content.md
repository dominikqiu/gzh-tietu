# 内容与分镜

## 两种入口

原文提炼：先列出原文问题、结论、依据和例外，挑一条主线。允许省去旁支，保留与主线相关的限定；在改编记录中列明省略范围。不是逐段压缩，也不是把每个章节变成一张挤满文字的卡。

选题创作：先明确读者面对的具体情境，再确定需要的事实材料。研究事实与编辑建议分开写。用户尚无材料时可先做标识为“待核实”的分镜草案，不将它作为已完成的事实型贴图交付。

## 五类配方

| 配方 | 默认五张组织方式 | JSON 内容卡 layout |
|---|---|---|
| 问题解答 | 问题首图／简答／条件／常见误区／结论 | qa |
| 规则对比 | 对比问题／维度一／维度二／适用边界／选择清单 | compare |
| 案例启示 | 案例问题／已知事实／争点与依据／适用边界／启示 | case |
| 操作清单 | 操作目标／准备／执行／复核／清单收束 | checklist |
| 学术导读 | 研究问题／文献信息／核心论证／争议或边界／阅读提示 | digest |

首图 layout=cover，收束 layout=summary，中间使用表中内容卡。无需凑满五张，避免每张重复同一句结论。规则对比建议两栏、每栏两三点；复杂对比拆维度。案例必须有真实来源，匿名示例和假设案例必须明示。学术导读保留作者、题名、卷期与页码，不根据题名推断未读全文。

## 文案

提供 3 个贴图标题候选、1 个选定标题、80—200 字短配文（均为建议长度）。标题让读者知道“解释什么”，不使用无依据的绝对词、恐吓或夸大收益。图中文字负责核心论点，配文补充情境与来源，不重复抄整组图卡。

法条与直接引文逐字对照，摘录标“节选”。解说用“解读／编辑建议”等标签；缺失的效力状态、日期、案例事实不现编。每张应可独立保存：标题、要点、必要条件与来源不能只存在于上一张。

保护原文含义是人工内容检查；渲染器只能检查结构、排版和文件产出。正式生成前将 `status` 设为 `ready`，代表创作者已核对材料；草稿设 `draft`，图片会显示“待核实草稿”。
